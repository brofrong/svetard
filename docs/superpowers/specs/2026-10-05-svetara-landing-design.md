# SVETARA — лендинг нутрициолога и персонального тренера

Дата: 2026-10-05
Статус: дизайн согласован, ожидает ревью спеки

## 1. Цель и контекст

Лендинг личного бренда **SVETARA**: один эксперт — нутрициолог и персональный тренер. Сайт продаёт:

- курсы по нутрициологии;
- персональные тренировки (онлайн / офлайн);
- комплекс «питание + тренировки».

Визуальный язык берётся из брендбука SVETARA: тёплая бежевая палитра, золото, арки, шёлк, тонкая типографика, слоган «Live. Feel. Choose.».

**Критерии успеха**

- Посетитель за один скролл понимает, кто эксперт, что он предлагает и сколько это стоит, и в один клик пишет в Telegram или WhatsApp.
- Сайт ощущается «премиально»: насыщенные, но плавные анимации на десктопе, без тормозов на мобильных.
- Контент (тексты, цены, фото, ссылки) меняется в одном файле без правок вёрстки.
- Архитектура позволяет позже добавить платформу (личный кабинет, уроки, оплата, блог) без переписывания лендинга.

**Вне рамок этой итерации:** личный кабинет, оплата, CMS, блог, форма заявки с бэкендом, мультиязычность, аналитика (подключается позже).

## 3. Архитектура

```
src/
  app/
    (marketing)/page.tsx     — лендинг, собирает секции по порядку
    (platform)/              — пусто, резерв под будущую платформу
    layout.tsx               — шрифты, метаданные, SmoothScroll, Cursor, Grain
    globals.css              — Tailwind + @theme токены
  content/site.ts            — ВЕСЬ контент: тексты, тарифы, FAQ, ссылки, пути к фото
  components/
    sections/                — по одному файлу на секцию (раздел 5)
    motion/                  — переиспользуемые эффекты (раздел 6)
    three/SilkHero.tsx       — WebGL-шёлк
    brand/Logo.tsx           — SVG логотип SVETARA и знак «S»
    ui/                      — Button, ArchImage, SectionHeading, Container
  lib/
    gsap.ts                  — регистрация плагинов GSAP в одном месте
    messenger.ts             — сборка ссылок Telegram/WhatsApp с предзаполненным текстом
    device.ts                — определение reduced-motion / слабого устройства / тач-ввода
public/images/               — фото-заглушки (скачанные локально)
tests/                       — Playwright
Dockerfile, .dockerignore
.github/workflows/docker.yml
biome.json
```

**Принципы**

- Секция — презентационный компонент: получает данные из `site.ts`, не содержит захардкоженных текстов.
- Эффекты инкапсулированы в обёртках из `motion/`. Секции только оборачивают в них элементы. Логика GSAP не размазывается по секциям, кроме уникальных сцен (горизонтальный скролл, экосистема, прелоадер).
- Все GSAP-анимации создаются через `useGSAP()` (`@gsap/react`) с автоматической очисткой при размонтировании.
- Клиентские компоненты (`"use client"`) — только там, где есть анимации или интерактив. Статическая разметка рендерится на сервере.

### 3.1 Модель контента (`site.ts`)

Типизированный объект `site` с полями:

- `brand` — имя, слоган, короткое описание.
- `contacts` — `telegram` (username), `whatsapp` (номер в международном формате), `instagram`, `email`.
- `nav` — пункты меню (label + якорь).
- `hero` — оффер, подзаголовок, тексты кнопок.
- `about` — фото, абзацы истории, регалии, `stats[]` (значение + подпись).
- `pains[]` — заголовок + описание.
- `path[]` — 5 этапов (Тело, Осознанность, Выбор, Трансформация, Сообщество): заголовок, 3 ключевых слова, описание, фото.
- `services[]` — заголовок, описание, фото, формат, `messengerText`.
- `program` — название курса, `modules[]` (номер, заголовок, пункты).
- `results` — `testimonials[]` (имя, текст, фото), `beforeAfter[]` (фото до, фото после, подпись).
- `pricing[]` — название, цена, период, пункты, `featured`, `messengerText`.
- `ecosystem[]` — узлы схемы (подпись, иконка).
- `faq[]` — вопрос + ответ.
- `cta` — заголовок финального блока, тексты кнопок.

Контент на старте — правдоподобные заглушки на русском про нутрициологию и тренировки.

### 3.2 Ссылки на мессенджеры (`lib/messenger.ts`)

- `telegramLink(text?)` → `https://t.me/<username>?text=<urlencoded>` (параметр `text` предзаполняет поле ввода; старые клиенты его игнорируют и просто открывают чат).
- `whatsappLink(text?)` → `https://wa.me/<номер без +>?text=<urlencoded>`.
- Обе функции дают на выходе ссылку на чат и без `text`.
- Все внешние ссылки открываются с `target="_blank" rel="noopener noreferrer"`.

### 4.2 Типографика

- Логотип — SVG (`brand/Logo.tsx`), характерная «Λ» вместо A. Варианты: словесный знак, знак «S» в круге, знак + слоган.
- Заголовки — **Cormorant Garamond** Light/Regular + Italic для акцентных слов.
- Текст, меню, кнопки — **Manrope**. Капс-подписи с `letter-spacing: 0.3em`.
- Оба шрифта подключаются через `next/font/google` с подмножествами `latin` + `cyrillic`.
- Размеры заголовков резиновые через `clamp()`.

### 4.3 Сетка и формы

- Контейнер `max-w-[1440px]`, 12 колонок, поля 24px (мобильные) / 48px (десктоп).
- Вертикальные отступы секций: 80px на мобильных, 120–160px на десктопе.
- Ключевая форма — **арка**: фото и карточки со скруглённым верхом (`rounded-t-full`).
- Тонкие линии в 1px (`taupe`/`gold`), короткие разделители «——» под заголовками.
- Кнопки в форме таблетки: основная — фон `espresso` и золотой текст, второстепенная — золотой контур.
- Тёмные секции (`espresso`): «Путь SVETARA» и финальный призыв.
- Фото: тёплая цветокоррекция. На весь сайт — лёгкое зерно (фиксированный слой поверх, `pointer-events: none`).

## 7. WebGL-шёлк (`three/SilkHero.tsx`)

- Полноэкранная плоскость, фрагментный шейдер: волнистые складки ткани на шуме, свет в палитре `ivory` → `sand` → `caramel` с золотыми бликами. Положение курсора мягко смещает складки.
- Подгружается через `next/dynamic` с `ssr: false` после основного контента. До загрузки и вместо WebGL показывается статичное фото шёлка (`next/image`, `priority`).
- WebGL **отключается** и остаётся фото, если: `prefers-reduced-motion: reduce`, нет поддержки WebGL, `pointer: coarse` и `hardwareConcurrency <= 4`.
- Рендер ставится на паузу, когда первый экран вне видимости (IntersectionObserver).
- `dpr` ограничен до `[1, 1.5]`.

## 8. Доступность и запасные варианты

- `prefers-reduced-motion: reduce` → Lenis, прелоадер, параллакс, курсор, притягивание и WebGL выключаются. Reveal-анимации заменяются мгновенным показом. Горизонтальный скролл в «Path» превращается в вертикальный список.
- Тач-устройства: без кастомного курсора и притягивания. Горизонтальный скролл остаётся (закреплённая секция работает с Lenis), остальные эффекты облегчены.
- Без JS: контент виден. Начальные скрытые состояния выставляет только GSAP при монтировании (`gsap.from`), CSS ничего не прячет. Прелоадер: маленький inline-скрипт в `<head>` ставит `html[data-intro="skip"]` (повторный визит в сессии или reduced-motion), CSS прячет прелоадер при `skip` и при `@media (scripting: none)`; страховочная CSS-анимация убирает его через 4 с, если JS не запустился.
- Семантика: один `<h1>`, иерархия заголовков, `alt` у изображений, аккордеоны на `<button aria-expanded>`, видимый focus-ring, все интерактивные элементы доступны с клавиатуры.
- SEO: `metadata` (title, description, Open Graph), `lang="ru"`, `robots.txt`, `sitemap.xml`, favicon из знака «S».

## 9. Изображения-заглушки

- Фото с Pexels (бесплатная лицензия) в стилистике брендбука (арки, шёлк, фитнес, еда, закат, группа людей). Unsplash блокирует автоматическое скачивание без API-ключа, у Pexels CDN доступен напрямую. Манифест `scripts/images.json` + скрипт `scripts/fetch-images.mjs` скачивают их в `public/images/`; внешние домены сайт не использует.
- Тёплая цветокоррекция задаётся CSS-фильтром на обёртке `ArchImage`, чтобы заглушки выглядели как одна серия. Фильтр отключается флагом, когда появятся настоящие фото.
- Все изображения выводятся через `next/image` с корректными `sizes`.
- Скрипт генерирует `public/images/CREDITS.md` со ссылками на исходные фото Pexels.

## 10. Деплой

### 10.1 Dockerfile

- `next.config.ts`: `output: "standalone"`.
- Многоэтапная сборка на `node:24-alpine` (Node 24 LTS):
  1. `deps` — pnpm через corepack, `pnpm install --frozen-lockfile`.
  2. `builder` — `pnpm build`.
  3. `runner` — копируются `.next/standalone`, `.next/static`, `public`. Пользователь не root (`nextjs:nodejs`), `ENV NODE_ENV=production PORT=3000 HOSTNAME=0.0.0.0`, `EXPOSE 3000`, `CMD ["node", "server.js"]`.
- `HEALTHCHECK` через `wget -qO- http://127.0.0.1:3000/api/health`. Роут `app/api/health/route.ts` возвращает `200 {"status":"ok"}`.
- `.dockerignore`: `node_modules`, `.next`, `.git`, `.github`, `tests`, `docs`, `playwright-report`, `test-results`.

### 10.2 GitHub Actions (`.github/workflows/docker.yml`)

- Триггеры: `push` в `main`, `push` тегов `v*`, `pull_request` в `main` (только проверки и сборка, без публикации), `workflow_dispatch`.
- Job `check`: pnpm + Node 24, `pnpm install --frozen-lockfile`, `pnpm exec biome ci`, `pnpm test` (Vitest), `pnpm build`.
- Job `docker` (`needs: check`): `permissions: { contents: read, packages: write }`; `docker/setup-buildx-action`; `docker/login-action` в `ghcr.io` через `GITHUB_TOKEN` (пропускается для `pull_request`); `docker/metadata-action`; `docker/build-push-action` с `cache-from/to: type=gha` и `platforms: linux/amd64`. `push: true` только для событий, отличных от `pull_request`.
- Образ: `ghcr.io/${{ github.repository_owner }}/svetara` (имя в нижнем регистре).
- Теги: `latest` и `sha-<short>` для `main`; `{{version}}` и `{{major}}.{{minor}}` для тегов `v*`; `pr-<n>` для PR (собирается, не публикуется).
